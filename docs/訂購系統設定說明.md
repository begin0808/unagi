# 線上訂購系統設定說明

網站的訂購表單會把訂單送到 Google Apps Script，由它寫進您自己的 Google 試算表並寄出通知信。
整個流程不需要主機、沒有月費，資料完全在您的 Google 帳號裡。

照著下面七個步驟做一次即可，之後都不用再動。

---

## 步驟 1：建立訂單試算表

1. 開啟 <https://sheets.new> 建立一份新的 Google 試算表。
2. 把檔名改成好認的名稱，例如 **興旺蒲燒鰻-訂單**。
3. 工作表不用先建，程式第一次收到訂單時會自動建立「訂單」工作表與標題列。

4. 順便把網址列中間那一長串「試算表 ID」複製起來，步驟 3 會用到：

   ```
   https://docs.google.com/spreadsheets/d/【這一長串就是 ID】/edit
   ```

## 步驟 2：開啟 Apps Script 編輯器

在剛才那份試算表上方選單點 **擴充功能 → Apps Script**。

> 建議一定要從這份試算表進去（這叫「繫結」），程式才知道預設要寫進哪一份表。
> 若您是從 script.google.com 另外開一個新專案，執行時會出現
> `You do not have permission to call SpreadsheetApp.getActiveSpreadsheet` 的錯誤，
> 這時請務必完成步驟 3 的 `SPREADSHEET_ID` 設定。

## 步驟 3：貼上程式碼

1. 編輯器會有一個預設的 `Code.gs`，把裡面原有的內容**全部刪掉**。
2. 打開本專案的 [`gas/Code.gs`](../gas/Code.gs)，複製全部內容貼上。
3. 按 **Ctrl + S** 存檔。

### 可以調整的地方（檔案最上方「設定區」）

| 常數 | 說明 |
|---|---|
| `SPREADSHEET_ID` | **建議直接填入**步驟 1 複製的試算表 ID。從試算表建立的專案可以留空，但填了最保險。 |
| `NOTIFY_EMAIL` | 新訂單通知信要寄到哪。**已寫在程式裡**（begin0808@gmail.com、lynnyl168168@gmail.com），貼上新版後不必重填。留空字串會自動寄給此指令碼的擁有者；多個收件者用逗號分隔。 |
| `PROMO_CODES` | 優惠碼清單，詳見下方「優惠碼」一節。 |
| `BANK_INFO` | 收款帳戶（銀行名稱、銀行代碼、帳號），詳見下方「付款方式」一節。銀行名稱與代碼已寫在程式裡，**帳號建議直接在 Apps Script 裡填寫** |
| `PAYMENT_DEADLINE_HOURS` | 轉帳與 LINE Pay 的付款期限，預設 48 小時 |
| `PRICE_PER_KG` | 每公斤售價，預設 1000 |
| `GIFT_BOX_PRICE`、`freeGiftBoxes()`、`maxGiftBoxes()` | 禮盒的加購價、免費額度與數量上限，詳見下方「送禮禮盒」一節 |
| `shippingFee()` | 運費級距，預設 1~2 包 $225、3~4 包 $290、5 包以上免運 |

> 這裡的價格若有修改，網站端的 `src/lib/pricing.ts` 也要改成一樣的數字，
> 否則顧客看到的金額會和實際記錄的金額對不上。

## 步驟 3.5：設定授權範圍（重要）

Apps Script 的權限是**第一次授權時就固定**的，之後改程式碼不一定會重新詢問，
常導致「填了 ID 卻還是說沒有權限」。先把需要的權限寫死在資訊清單檔就不會有這個問題。

1. 編輯器左側點 **專案設定**（齒輪圖示）。
2. 勾選 **在編輯器中顯示「appsscript.json」資訊清單檔案**。
3. 回到左側 **編輯器**，檔案清單會多出 `appsscript.json`，點開它。
4. 把內容整個換成本專案的 [`gas/appsscript.json`](../gas/appsscript.json)：

   ```json
   {
     "timeZone": "Asia/Taipei",
     "dependencies": {},
     "exceptionLogging": "STACKDRIVER",
     "runtimeVersion": "V8",
     "oauthScopes": [
       "https://www.googleapis.com/auth/spreadsheets",
       "https://www.googleapis.com/auth/script.send_mail",
       "https://www.googleapis.com/auth/userinfo.email"
     ],
     "webapp": {
       "executeAs": "USER_DEPLOYING",
       "access": "ANYONE_ANONYMOUS"
     }
   }
   ```

5. **Ctrl + S** 存檔。

## 步驟 4：先執行一次測試

1. 編輯器上方的函式下拉選單選 **`testWrite`**，按 **執行**。
2. 第一次執行會跳出授權視窗：
   - 點「檢閱權限」→ 選您的 Google 帳號
   - 出現「Google 尚未驗證這個應用程式」→ 點左下角 **進階 → 前往「專案名稱」（不安全）**
   - 這是您自己寫的程式，安全無虞，按 **允許**
3. 回到試算表，應該會看到一筆「測試訂單」，也會收到一封通知信。
4. **確認無誤後，把那一列測試資料刪掉。**

## 步驟 5：部署為網頁應用程式

1. 編輯器右上角點 **部署 → 新增部署作業**。
2. 左邊齒輪選 **網頁應用程式**。
3. 設定如下：

   | 欄位 | 要選的值 |
   |---|---|
   | 說明 | 訂單接收（可自由填寫） |
   | 執行身分 | **我**（您自己的帳號） |
   | 誰可以存取 | **所有人** |

   > 「誰可以存取」一定要選**所有人**，否則顧客的瀏覽器會被擋下來。
   > 這不代表任何人能看到您的試算表，他們只能送訂單進來。

4. 按 **部署**，複製產生的**網頁應用程式網址**，長得像：

   ```
   https://script.google.com/macros/s/AKfycb.....................hQ/exec
   ```

5. 把這串網址貼到瀏覽器打開，看到 `{"ok":true,"service":"興旺蒲燒鰻 訂單接收服務",...}` 就代表成功。

## 步驟 6：把網址填進網站

目前的部署網址**已經寫在程式碼裡**，位於
[`src/components/OrderForm.tsx`](../src/components/OrderForm.tsx) 最上方的
`DEFAULT_ORDER_API_URL`。網站已經接好，這一步平常不需要做任何事。

### 什麼時候需要改？

只有在**重新部署導致網址改變**時（見下方「修改程式後要重新部署」）。改法二選一：

**A. 直接改程式碼**（簡單）

把 `DEFAULT_ORDER_API_URL` 的字串換成新網址，`npm run build` 後推送即可。

**B. 用環境變數覆蓋**（不動程式碼）

在專案根目錄建立 `.env`（可複製 `.env.example` 改名）：

```
VITE_ORDER_API_URL=https://script.google.com/macros/s/新的網址/exec
```

`.env` 已被 `.gitignore` 排除，不會上傳到 GitHub。
若要讓正式站也吃到，需再到 Vercel → **Settings → Environment Variables**
新增同名變數，然後回 **Deployments** 對最新一筆點 **Redeploy**。

> 這串網址本來就會出現在網頁送出的請求中，瀏覽器一定看得到，
> 所以放在程式碼裡並不會降低安全性。

## 日常使用

- **看訂單**：直接開那份 Google 試算表。最右邊的「處理狀態」欄可以自己改成「已聯繫」「已出貨」等。
- **匯出 Excel**：試算表選單 **檔案 → 下載 → Microsoft Excel (.xlsx)**。
- **欄位**：訂單編號／訂單時間／姓名／電話／地址／Email／**LINE ID**／規格 A B C／總公斤／
  包裝方式／禮盒數／商品金額／禮盒金額／運費／優惠碼／折扣金額／總金額／
  **取貨方式**／**付款方式**／**匯款人姓名**／**匯款後五碼**／備註／處理狀態
- **處理狀態是下拉選單**：轉帳訂單一開始是「待付款」，面交付現的訂單是「待取貨」。
  之後依序改成已付款 → 已出貨 → 已完成；取消的訂單改成「已取消」即可，不建議直接刪除整列。
- 「包裝方式」是自用或送禮；送禮才會有禮盒數。
  「禮盒金額」欄記錄加購禮盒的金額，全部在免費額度內時為 0。
- **訂單編號**：格式為 `XW20260906-001`，每天從 001 重新開始。

## 付款方式

| 取貨方式 | 可選的付款方式 | 運費 |
|---|---|---|
| 黑貓冷凍宅配 | 銀行轉帳、LINE Pay | 依公斤數，滿 5 公斤免運 |
| 臺南面交（三處擇一） | 銀行轉帳、LINE Pay，或取貨時付現 | 免運費 |

面交地點限以下三處擇一，由賣家打電話與顧客約時間：臺南永康全家永德店、國立南大附中、金葡萄蛋黃酥復國店。
試算表「地址」欄會記成「面交：地點（顧客方便的時段）」，新訂單通知信也會提醒賣家打電話約時間。
地點若要增減，`src/lib/pricing.ts` 與 `gas/Code.gs` 的 `PICKUP_SPOTS` 兩邊都要改。

### 設定收款帳戶

在 Apps Script 編輯器的 `Code.gs` 設定區找到 `BANK_INFO`，填入收款帳戶：

```javascript
const BANK_INFO = {
  bankName: '中國信託商業銀行',  // 銀行名稱（不列分行）
  bankCode: '822',              // 銀行代碼（3 碼）
  account: '00000000000000',    // 帳號（只填數字）← 只要填這個
};
```

確認信只列銀行名稱、銀行代碼與帳號，不列分行與戶名。銀行名稱與代碼已寫在程式裡，只要填帳號，存檔後重新部署（新版本）。
**帳號沒填的話**，確認信會改成「我們會盡快與您聯繫，提供匯款帳號」，不會出現空白或錯誤的帳號。

> 跟 `SPREADSHEET_ID` 一樣，建議只在 Apps Script 裡填，不要寫進 GitHub 上的 `gas/Code.gs`。
> **每次貼上新版程式碼後，記得把這幾個值重新填回去。**

### LINE Pay 付款流程

賣家不公開自己的 LINE ID，改由賣家主動加顧客，不需要任何設定：

1. 顧客選「LINE Pay」時，**必須填寫自己的 LINE ID**（網頁會檢查格式：4~20 個英文、數字或 . _ -）。
2. 賣家收到的新訂單通知信會寫「請用 LINE 搜尋 ID『xxx』加顧客好友」，試算表「LINE ID」欄也會記錄。
3. 賣家加好友後，傳送 LINE Pay 收款方式；顧客轉帳時在留言填寫訂單編號。
4. 對帳後把「處理狀態」改成「已付款」再出貨。

- 確認信會提醒顧客開啟「允許利用 ID 加入好友」。若還是搜尋不到，請改用電話聯繫。
- LINE Pay 個人轉帳的條件（實名認證、轉帳上限等）以 LINE Pay 官方說明為準，建議先找朋友試轉一筆。

### 客人會看到什麼

- **選銀行轉帳**：**收款帳號只寫在訂單確認信裡，網頁畫面不顯示**。一定要填寫真實的 Email 才拿得到帳號，
  亂填或機器人下的單看不到。送出後的畫面會提示「匯款帳號已寄到您的 Email」與付款截止時間（下單後 48 小時），
  並提醒客人查看垃圾郵件匣。確認信列出銀行名稱、銀行代碼、帳號、應付金額與截止時間。
- **匯款人姓名、匯款帳號後五碼都是選填**：已確定要用哪個帳戶的人可以先填；
  還不確定的人轉帳後回覆確認信告知即可，不會被表單卡住。
- **只有選 LINE Pay 時才會詢問 LINE ID（必填）**，記在試算表「LINE ID」欄；其他付款方式這一欄是空白。
- 確認信會提醒客人：**本店不會以電話或 LINE 通知更改匯款帳號**，收到類似通知請勿匯款。
- **選 LINE Pay**：客人必須填寫自己的 LINE ID，由賣家加客人好友並傳送付款方式；客人轉帳時**在留言填寫訂單編號**。
  付款期限一樣是下單後 48 小時，確認收款後才出貨。
- **選取貨時付現**（僅限面交）：畫面與信件會說明將由賣家打電話約定面交時間。

### 對帳

打開網路銀行的入帳紀錄，用「金額＋匯款人姓名／匯款後五碼」對照試算表，對上了就把「處理狀態」改成「已付款」再安排出貨。
LINE Pay 的訂單請看 LINE Pay 的收款紀錄，用「金額＋轉帳留言的訂單編號」對照。
超過期限仍未付款的訂單，可以先聯繫確認，或改成「已取消」。

### 收款與防詐注意事項

1. **款項要對得上訂單才出貨。** 金額、訂購人或匯款人姓名、匯款後五碼都要對得上。
2. **遇到下面這些情況，先打電話給訂購人確認，再出貨：**
   - 匯款人姓名與訂購人不同
   - 收到一筆對不上任何訂單的款項
   - 第一次下單的陌生客人訂購大量商品，又急著要出貨

   這是為了防範「三方詐騙」：騙子用您的網站下單、填自己的收件地址，同時騙另一位受害者匯款到您的帳戶。
   您出貨給騙子之後，受害者一報警，**您的帳戶可能被列為警示帳戶而凍結**。
3. **收到來路不明的款項，不要自行退款**，也不要依對方要求轉到其他帳戶。請先聯絡銀行，必要時撥打 165 反詐騙專線。
4. **建議使用專門收貨款的帳戶**，萬一出問題，也不會影響日常使用的主要帳戶。
5. **本店不會以電話或 LINE 通知客人更改匯款帳號。** 確認信裡已提醒客人這一點；
   若有客人反映收到「帳號變更」的通知，那是冒名詐騙，請提醒他不要匯款。

## 送禮禮盒

客人在訂購時選擇「自用」或「送禮」：

- 選**自用**：不附禮盒
- 選**送禮**：可自行選擇要幾個禮盒

每條鰻魚都是單獨真空包裝，一個禮盒約可裝 3~4 條，所以「需要幾個禮盒」取決於
要分送幾位對象，跟買了幾公斤沒有直接關係。

| 項目 | 規則 |
|---|---|
| 免費額度 | 購買公斤數（買 2 公斤免費附 2 個） |
| 加購 | 超過免費額度的部分，每個 $50 |
| 數量上限 | 總條數（極端情況一條一盒，不可能再更多） |

例如買 2 公斤小條鰻魚（4 條／公斤，共 8 條），要分送三位親友時可選 3 個禮盒，
其中 2 個免費、第 3 個加購 $50。上限是 8 個。

上限與免費額度**前端與後端各算一次**。客人若先選了較多禮盒再減少商品，
網站會自動下修並顯示提示；就算有人改前端送出更大的數字，`Code.gs` 也會重新夾住並重算金額。

要調整規則的話，`src/lib/pricing.ts` 的 `freeGiftBoxes()`、`maxGiftBoxes()`、
`GIFT_BOX_PRICE` 與 `Code.gs` 的同名項目要一起改。

> 「禮盒金額」欄記錄的是加購金額；全部都在免費額度內時為 0。

## 優惠碼

給熟識朋友使用的折扣碼。規則是**以商品金額（不含禮盒與運費）每滿 1,000 元折抵一次**，
不足一階的零頭不計，不設上限。**每一階折抵多少由各個碼自己決定**：

| 商品金額 | `XW50` 折抵 | `XW100` 折抵 |
|---|---|---|
| 1,000（1 公斤） | 50 | 100 |
| 2,000（2 公斤） | 100 | 200 |
| 3,000（3 公斤） | 150 | 300 |
| 5,000（5 公斤） | 250 | 500 |

### 怎麼改優惠碼

在 `Code.gs` 設定區找到這一段：

```javascript
const PROMO_CODES = [
  { codes: ['XW50'],  discountPerStep: 50 },   // 每滿 1,000 折 50
  { codes: ['XW100'], discountPerStep: 100 },  // 每滿 1,000 折 100
];
```

- **換碼**：改 `codes` 裡的字
- **改折扣**：改 `discountPerStep` 的數字
- **加一組**：照樣子多寫一行
- **設別名**：`codes` 填多個，例如 `{ codes: ['XW50', '荒野'], discountPerStep: 50 }`，
  兩種寫法都能用。**中文優惠碼可以**
- **停用優惠碼功能**：`const PROMO_CODES = [];`

比對時**不分大小寫、自動去除所有空白、全形字自動轉半形**，
所以「xw50」「ＸＷ５０」「 XW 50 」都能通過，客人怎麼打都不會卡住。

改完存檔後，必須走下方「修改程式後要重新部署」的步驟才會生效。

### 為什麼優惠碼不能寫在網站裡

網頁的原始碼任何人都能打開來看。優惠碼若寫在網站程式碼中，等於直接公告給所有訪客，
「熟識朋友專屬」就沒有意義了。

所以流程設計成：客人在網站輸入碼 → 按「套用」→ 網站把碼送到這支 Apps Script 問「對不對」
→ **驗證通過才回傳該碼的折扣額度**給網頁計算，無效時什麼都不透露，
沒有碼的訪客完全看不到有哪些碼、折多少。

送出訂單時會**再查一次表並重算金額**，前端說「已套用」不算數，以後端算出來的為準。

### 試算表會自動加兩欄

啟用優惠碼後，試算表會在「運費」右邊自動插入**優惠碼**與**折扣金額**兩欄。
既有的訂單資料會由 Google 試算表自動右移，不會錯位，折扣金額補 0。
這個動作只會執行一次，之後不會重複。

### 測試

編輯器的函式下拉選單選 **`testPromo`** 按執行，可以只測優惠碼驗證（不會寫入任何資料）。
執行記錄會顯示正確的碼、大小寫變化的碼、以及錯誤的碼分別回傳什麼。

## 修改程式後要重新部署

改完 `Code.gs` 存檔後，要按 **部署 → 管理部署作業 → 編輯（鉛筆圖示）→ 版本選「新版本」→ 部署**。
用這個方式網址不會變，網站端不用改。

（如果按「新增部署作業」會產生**新的網址**，那就必須回到步驟 6 更新網址。）

## 疑難排解

| 狀況 | 原因與處理 |
|---|---|
| 網站顯示「尚未設定訂單接收網址」 | `.env` 沒設定，或設定後沒重新啟動 `npm run dev`／沒在 Vercel 重新部署 |
| 送出後顯示失敗 | 多半是部署時「誰可以存取」沒選「所有人」。回步驟 5 檢查 |
| 沒收到通知信 | 檢查垃圾郵件匣；或在 `NOTIFY_EMAIL` 明確填入信箱 |
| 優惠碼一直顯示「不正確」 | 多半是改了 `PROMO_CODES` 但沒有重新部署新版本，線上跑的還是舊版 |
| 試算表沒有新增資料 | 到 Apps Script 編輯器左側「執行項目」看錯誤訊息 |
| `You do not have permission to call SpreadsheetApp.getActiveSpreadsheet` | 這個專案沒有跟試算表繫結。在設定區的 `SPREADSHEET_ID` 填入試算表 ID，存檔後重新執行 `testWrite` 並重新授權即可 |
| `You do not have permission to call SpreadsheetApp.openById`，而且**沒有跳出授權視窗** | 舊的授權範圍不夠但系統沒有重新詢問。先完成步驟 3.5 設定 `appsscript.json`；若仍不跳出，到 <https://myaccount.google.com/permissions> 找到這個專案按「移除存取權」，再回來執行 `testWrite` 就會重新授權 |
| 重新授權時權限說明變成「查看、編輯、建立及刪除您的所有 Google 試算表檔案」 | 填了 `SPREADSHEET_ID` 之後就是這個範圍，屬正常現象。程式只會動到您指定的那一份試算表 |

## 已知限制

- **這不是金流系統。** 顧客以銀行轉帳或面交付現付款，入帳需由您對照網銀紀錄（金額＋匯款人姓名／匯款後五碼）人工核對，並在試算表把「處理狀態」改為「已付款」。
- **部署網址無法真正保密**，它一定會出現在網頁的程式碼裡。程式已內建防機器人的隱藏欄位與欄位檢核，但擋不住有心人手動灌假訂單。試算表裡看到明顯亂填的直接刪除即可。
- Gmail 免費帳號每天寄信上限約 100 封，以目前訂單量不會觸及。
- 若送單失敗，畫面會提供原本的 Google 表單作為備援管道，顧客仍下得了單。
